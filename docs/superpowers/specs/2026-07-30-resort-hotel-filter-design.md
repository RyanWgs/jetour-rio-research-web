# Resort 酒店分类筛选设计

日期：2026-07-30

## 目标

在中英文版本的「03 酒店配套 / Hotel Support」中增加酒店角色分类筛选，让管理层可以直接查看度假型酒店，同时保留现有场地关联筛选。

## 页面结构

酒店模块新增一个「酒店类型 / Hotel Type」下拉筛选：

- 中文：全部酒店、主酒店、VIP酒店、补充酒店、度假型酒店
- 英文：All Hotels、Main Hotel、VIP Hotel、Support Hotel、Resort

酒店类型筛选与现有「对应项目场地 / Linked Venue」筛选同时存在，并采用交集逻辑。例如选择“度假型酒店”及“Ipanema / Arpoador”，只显示同时满足两项条件的酒店。

## 数据规则

沿用酒店资料现有的 `hotelRole` 字段作为唯一分类依据：

- `main_hotel`：主酒店 / Main Hotel
- `vip_hotel`：VIP酒店 / VIP Hotel
- `support_hotel`：补充酒店 / Support Hotel
- `resort_hotel`：度假型酒店 / Resort

首批 Resort 为已标记的 Sheraton Grand Rio Hotel & Resort。其他酒店不会仅因名称、泳池或临海位置自动归为 Resort；只有资料明确显示度假村属性及相对完整的住宿、休闲和海滩体验时才调整分类。

## 交互规则

- 进入酒店模块时默认显示全部酒店。
- 切换酒店类型后立即更新卡片数量和结果。
- 切换模块时重置酒店类型筛选。
- 从场地详情点击“查看配套酒店”时，酒店类型保持默认“全部酒店”，避免误隐藏关联酒店。
- 搜索、排序、收藏筛选继续与酒店类型筛选组合生效。
- 酒店卡片和详情页继续显示双语角色标签。

## 验证标准

- 中文版可见五个酒店类型选项，英文版可见对应五个英文选项。
- 选择 Resort 时只显示 `resort_hotel` 记录。
- 酒店类型与场地筛选交集结果正确。
- 中英文其他模块、收藏和详情弹窗不受影响。
- 桌面端与手机端沿用现有响应式筛选布局。
